# IAM Authentication & Registration System

A robust, production-ready **Identity and Access Management (IAM)** and Authentication backend built with **Node.js**, **Express**, **TypeScript**, **PostgreSQL**, and **Drizzle ORM**. 

The system implements security standards including password hashing, Multi-Factor Authentication (MFA), Email and SMS OTP verification, session management, and JWT access/refresh token rotation using a clean **Model-View-Controller (MVC)** design pattern.

---

## 🚀 Features

- 🔐 **User Registration & Password Hashing**: Secure password storage using `bcryptjs` salt hashing.
- ✉️ **Email OTP Verification**: Generation, dispatch, and verification of 6-digit OTP codes for email verification.
- 📱 **SMS OTP Verification**: Generation, dispatch, and verification of 6-digit OTP codes for phone number verification.
- 🔑 **Multi-Factor Authentication (MFA)**: Support for MFA-enabled user logins requiring OTP verification before session issuance.
- 🎫 **JWT & Session Management**: Dual support for HTTP-only cookies and Bearer tokens with active PostgreSQL session tracking.
- 🔄 **Token Refreshing**: Token exchange endpoint (`POST /api/token`) to renew expired access tokens using valid refresh tokens or sessions.
- 🛡️ **Protected Route Middleware**: Middleware (`authenticateToken`) for route authorization.
- 🏗️ **Clean MVC Architecture**: Strict separation of concerns across routes, controllers, models, and ORM schemas.

## 🗄️ Database Schema

### `users`
| Column | Type | Constraints / Default |
| :--- | :--- | :--- |
| `id` | `uuid` | Primary Key, `gen_random_uuid()` |
| `email` | `text` | Unique, Not Null |
| `password_hash` | `text` | Not Null |
| `phone` | `text` | Nullable |
| `email_verified` | `boolean` | Default `false`, Not Null |
| `phone_verified` | `boolean` | Default `false`, Not Null |
| `mfa_enabled` | `boolean` | Default `false`, Not Null |
| `created_at` | `timestamp` | Default `now()`, Not Null |
| `updated_at` | `timestamp` | Default `now()`, Not Null |

### `sessions`
| Column | Type | Constraints / Default |
| :--- | :--- | :--- |
| `id` | `uuid` | Primary Key, `gen_random_uuid()` |
| `user_id` | `uuid` | Foreign Key -> `users(id)` (CASCADE), Not Null |
| `expires_at` | `timestamp` | Not Null |
| `created_at` | `timestamp` | Default `now()`, Not Null |

### `otps`
| Column | Type | Constraints / Default |
| :--- | :--- | :--- |
| `id` | `uuid` | Primary Key, `gen_random_uuid()` |
| `user_id` | `uuid` | Foreign Key -> `users(id)` (CASCADE), Nullable |
| `type` | `text` | Not Null (`email_verify`, `phone_verify`, `login_mfa`) |
| `target` | `text` | Not Null (Email address or phone number) |
| `code` | `text` | Not Null (6-digit OTP code) |
| `expires_at` | `timestamp` | Not Null |
| `used` | `boolean` | Default `false`, Not Null |
| `created_at` | `timestamp` | Default `now()`, Not Null |

## 🔌 API Endpoints Summary

### Public Auth Endpoints

| Method | Endpoint | Description | Request Body Example |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/register` | Register a new user | `{ "email": "user@example.com", "password": "SecretPassword123!", "phone": "+1234567890", "mfa_enabled": false }` |
| `POST` | `/api/send-email-otp` | Send email verification OTP | `{ "email": "user@example.com" }` |
| `POST` | `/api/verify-email-otp` | Verify email OTP code | `{ "email": "user@example.com", "code": "123456" }` |
| `POST` | `/api/send-sms-otp` | Send SMS verification OTP | `{ "phone": "+1234567890" }` |
| `POST` | `/api/verify-sms-otp` | Verify SMS OTP code | `{ "phone": "+1234567890", "code": "654321" }` |
| `POST` | `/api/login` | Login user (Triggers MFA if enabled) | `{ "email": "user@example.com", "password": "SecretPassword123!" }` |
| `POST` | `/api/verify-login-otp` | Complete login with MFA OTP | `{ "email": "user@example.com", "code": "987654" }` |
| `POST` | `/api/token` | Refresh JWT access token | `{ "refreshToken": "<JWT_REFRESH_TOKEN>", "sessionId": "<SESSION_ID>" }` |

### Protected Endpoints *(Requires `Authorization: Bearer <token>` or Session Cookie)*

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/me` | Retrieve profile of the currently authenticated user |
| `POST` | `/api/logout` | Revoke active session and clear authentication cookies |
| `GET` | `/api/protected` | Sample protected resource endpoint |

## ⚡ Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) (v18+ recommended)
- [pnpm](https://pnpm.io/) package manager
- [PostgreSQL](https://www.postgresql.org/) database running locally or hosted

### Installation & Environment Setup

1. **Clone the repository**:
   ```bash
   git clone <repository-url>
   cd Auth-System(assignment)
   ```

2. **Install dependencies**:
   ```bash
   pnpm install
   ```

3. **Configure environment variables**:
   Create a `.env` file in the project root (refer to `.env.example`):
   ```env
   DATABASE_URL=postgres://postgres:postgres@localhost:5432/auth_db
   PORT=3000
   JWT_SECRET=your_super_secret_jwt_key
   ```

4. **Run database migrations**:
   ```bash
   # Generate Drizzle migration files
   pnpm db:generate

   # Push schema changes directly to PostgreSQL
   pnpm db:push
   ```

## 🔒 Security Best Practices Implemented

- **Password Safety**: Passwords are never stored in plain text. Always hashed with `bcryptjs`.
- **Sanitized Outputs**: User objects returned by API responses automatically strip `password_hash`.
- **OTP Lifecycle**: OTPs expire after a configured time window (5 to 10 minutes) and are marked `used` immediately upon verification to prevent replay attacks.
- **Foreign Key Cascading**: Deleting a user automatically purges associated sessions and OTP records.
- **ESM & NodeNext Compliance**: Strictly typed ESM imports adhering to Node.js ESM specifications.
